# Seasons of Orbis

The yearly-events pack (plugin id `Ziggfreed:SeasonsOfOrbis`, folder `mods/seasons-of-orbis`; its GitHub repository keeps the `HallowsEvePack` name, as do Hallow's Eve's `HallowsEvePack` asset folders): Hallow's Eve, Harvest Feast and Hytale's Anniversary. The family-wide rules apply here; this file adds only what is specific to this pack. Routers under `Server/ZiggfreedCommon/` (reputations, placements, the `Season` leaf, bases), `Server/Item/` (throw chains, Lantern Bomb blasts) and `Common/` (generated art) hold the rest.

- The MMO is optional: the manifest hard-depends on ZiggfreedCommon and RPG Stations (the Carving Bench is an RPG Stations station, and a pack file naming another mod's interaction Type stops a server without that mod at boot) and names MMO Skill Tree under `OptionalDependencies`, which only orders the load (the pack's copy of a shared id loads last). Author MMO content in string vocabularies (reward and objective kinds, factors, stat ids, channels), never a codec `Type` or dialogue shorthand the MMO registers: without the MMO that fails the pack's decode (mmo-skills' `SeasonsOfOrbisMmoGateScanTest` holds this and the gate rule below).
- The MMO's pay for a quest, contract or achievement is `Mmo_Xp` and `Mmo_Boost_Token` rows in that file's own `Rewards` (skill XP in the skill the work trains), each with its own `"Requires": { "Factors": [ { "Factor": "hytale:mod_installed", "Param": "Ziggfreed:MMOSkillTree", "Min": 1 } ] }`, which leaves the row out without the MMO while the rest of the file pays; a contract or offer keeps a plain row beside it, since one whose every row is gated pays nothing there (EMPTY_REWARDS) (`SeasonsOfOrbisMmoRowsTest`, `SeasonsOfOrbisMmoGateScanTest`). No MMO file, in the jar or here, tops up a pay table the pack's own rows already pay through.
- The rest of each season's MMO layer ships here as additive contributions (`ContributesTo`, extensions); a same-id override only where a contribution cannot express it. Such a zc-store file carries the same condition as a top-level `Requires` (always `Min 1`), which zc drops at load without the MMO; a file in the MMO's own stores (`Server/MMOSkillTree/`) or an RPG Stations extension on the `mmoskilltree:skill_xp` channel needs none. Its words go in the season's pack-owned lang file (`hallowseve.mmo.lang`, `harvestfeast.mmo.lang`), never `mmoskilltree.lang`.
- Ids carry their season's prefix (`Hallows_Eve_`, `Harvest_Feast_`, `Hytale_Anniversary_`) or the cross-season `Seasons_Of_Orbis_`, with `Mmo_` before it in an MMO layer; quests and achievements sit under a `_<Season>` folder the folded id spells (`HallowsEvePack/_Hallows_Eve`, `SeasonsOfOrbis/_Harvest_Feast`).
- A season's creatures exist only through `ZiggfreedCommon/CalendarSpawns`, except a boss's forms, head and adds, which only his encounter script raises (`Server/EncounterManager/`): one native world-spawn rule per creature and environment (the game refuses a second), and Harvest Moon rewrites the same `Rule` ids at a higher `Priority`, never a rule of its own. Their roles are Variants of the vanilla templates carrying the vanilla creature's own `Modify`, never Variants of the creature itself: a Variant's `Modify` reaches only its immediate Reference's `Parameters`, and any other key refuses the whole role while the boot reads PASS, so grep the boot for `does not exist or is private`.
- The pack carries its own nine-locale lang files.
- The items carry no calendar gate; only the bench's `Carve_Hallowed` action locks on `calendar_live`.
- Hallow's Eve's MMO layer keeps the ids the MMO jar first shipped it under (`Mmo_Hallows_Eve_*` and the XP map `Hallows_Eve`, in `HallowsEvePack` folders); the jar carries no copy, so this pack's files and `hallowseve.mmo.lang` are the only ones (`HallowsEveJarContentTest`, `HallowsEveMmoLangTest`). Its five MMO-store and RPG Stations files carry no mod gate; its six zc-store files carry the mod gate, and only the four skill dailies keep a typed `Hallows_Eve_Live` running switch beside it.
- A boss's bombs never share the Lantern Bomb files: the shared `Orbis_Boss_*` bursts and fire patch match `Player` only (`{"Type": "Player"}`, the patch's `TargetTypes`), so a boss and his adds are never hurt, and they burn with vanilla `Burn`, never `Hallows_Eve_Lantern_Burn`, whose Hit tag pays the MMO's Artillery XP.
- A boss arena's prefab under `Server/Prefabs/` is generated: `tools/arena_markers.py` writes it from its source prefab and its spec in `tools/arenas/` (the fight's entity, spawn markers, exit pads), so change the spec and rerun it (`--check` compares), never hand-edit the output.

# Seasons of Orbis

The yearly-events pack (plugin id `Ziggfreed:SeasonsOfOrbis`; repository and folder keep the `HallowsEvePack` / `hallows-eve-pack` name), whose first event is Hallow's Eve. The family-wide rules apply here; this file adds only what is specific to this pack.

- The MMO is optional: the manifest hard-depends on ZiggfreedCommon and RPG Stations (the Carving Bench is an RPG Stations station) and names MMO Skill Tree under `OptionalDependencies`, which only orders the load (the pack's copy of a shared id loads last). Author MMO content in string vocabularies (reward and objective kinds, factors, stat ids, channels), never a codec `Type` or dialogue shorthand the MMO registers: without the MMO that fails the pack's decode (the root's `SeasonsOfOrbisMmoGateScanTest` holds this and the gate rule below).
- The MMO's pay for a quest, contract or achievement is `Mmo_Xp` and `Mmo_Boost_Token` rows in that file's own `Rewards` (skill XP in the skill the work trains), which a server without the MMO skips at payout and hides on every reward panel, with one log warning each until zc's row-level mod gate lands (`SeasonsOfOrbisMmoRowsTest`). No MMO file, in the jar or here, tops up a pay table the pack's own rows already pay through.
- The rest of each season's MMO layer ships here as additive contributions (`ContributesTo`, extensions); a same-id override only where a contribution cannot express it. Such a zc-store file carries the top-level `{"Factor": "hytale:mod_installed", "Param": "Ziggfreed:MMOSkillTree", "Min": 1}` (always `Min 1`), which zc drops at load without the MMO; a file in the MMO's own stores (`Server/MMOSkillTree/`) or an RPG Stations extension on the `mmoskilltree:skill_xp` channel needs none. Its words go in a pack-owned lang file (`hallowseve.mmo.lang`), never `mmoskilltree.lang`.
- Ids are prefixed `Hallows_Eve_`; quests and achievements sit under `_Hallows_Eve` folders.
- The event's creatures exist only through `ZiggfreedCommon/CalendarSpawns`: one native world-spawn rule per creature and environment (the game refuses a second), and Harvest Moon rewrites the same `Rule` ids at a higher `Priority`, never a rule of its own. Their roles are Variants of the vanilla templates carrying the vanilla creature's own `Modify`, never Variants of the creature itself: a Variant's `Modify` reaches only its immediate Reference's `Parameters`, and any other key refuses the whole role while the boot reads PASS, so grep the boot for `does not exist or is private`.
- The two reputations, Old Jack's Favor and the Hallowed, are native `ReputationGroup`s (`Server/NPC/Reputation/Groups/`) with zc companions (`ZiggfreedCommon/Reputations/HallowsEvePack/`), and favor is paid on each quest's and contract's own rewards (a `Reputation` reward), never inside the shared pay lootables, so the quest card shows it.
- Old Jack's placement names `"Season": "Hallows_Eve"`, with `Lifecycle.KeepAlive`, and the library sweeps placements at every calendar start and end; his role names only the quest-giver template's five parameters.
- The pack carries its own nine-locale lang files.
- A pack file naming another mod's interaction Type stops a server without that mod at boot (the zip fails asset validation), which is why the pack requires RPG Stations rather than treating it as optional. The items carry no calendar gate; only the bench's Carve_Hallowed action locks on calendar_live.
- Everything event-only vanishes when the event or its kill switch is off: the `Season` leaf (`"Season": "Hallows_Eve"`; the Harvest Moon bundle names `Harvest_Moon`) hides a file (a placement, the wallet, the storefront, the board, an offer, a contract, a quest, the trick-or-treat extension). A `Parent` base carries it to every child whatever `Requires` the child writes; never gate a season through a base's `Requires`, which a child's own replaces whole. `ziggfreedcommon:calendar_live` is for locks and rolls only. Achievements carry no gate: their `Occurrence` keeps each year's copy live only while that year runs. The items stay plain native assets.
- A `Parent` skeleton for files under `_Hallows_Eve/` sits outside that folder, named so its filename already spells its id (`Achievements/HallowsEvePack/Hallows_Eve_Hallowed_Base.json`): the engine resolves `Parent` by filename and the root content test by folded id, and only such a name satisfies both.
- Quests, offers and contracts at Old Jack stand on Abstract bases outside the `_Hallows_Eve` folder (`Quests/HallowsEvePack/Hallows_Eve_Quest_Base.json`, `ShopEntries/HallowsEvePack/Hallows_Eve_Offer_Base.json`, `Bounties/HallowsEvePack/Hallows_Eve_Contract_Base.json`) that carry shape and `Season`, never `Requires` or `Objectives`. The four Lantern Bomb offers come from `ShopEntryGenerators/HallowsEvePack/Hallows_Eve_Lantern_Bomb_Offers.json`, whose `IdPattern` spells the ids players' purchase counts are filed under. The three dailies stay hand-written: their steps differ in which leaves they write, and an empty `Qualifier` changes what counts. The root's `HallowsEveRetrofitPinTest` holds every shipped id to its frozen meaning: a deliberate change adds an allowance there with its own test, and never touches the frozen tree.
- Hallow's Eve's layer keeps the MMO jar's ids (`Mmo_Hallows_Eve_*` and the XP map `Hallows_Eve`, in `HallowsEvePack` folders) and stays equal to the jar's copy while that copy ships (`HallowsEveLayerTwinTest`, `HallowsEveMmoLangTest`). Its five MMO-store and RPG Stations files carry no mod gate; its six zc-store files carry the mod gate, and only the four skill dailies keep a typed `Hallows_Eve_Live` running switch beside it.
- A throw or crack chain is one Serial in the game's own order: the projectile (or the spend) first and the credit beside it, with the bomb spent last, or the payout inside the spend's Next. A Parallel forks the spend, and on the last item the engine's item-change check ends the throw still waiting on the client.
- Every Lantern Bomb blast spares players through one HitEntityRules rule, {Type Player, Invert true}, and no plain HitEntity: in a projectile's chain IgnoreOwner skips the projectile, never the thrower.
- The art under Common/ is generated: change tools/derive_art.py and rerun it, never hand-edit a file it writes. It reads byte copies of the vanilla files it needs from tools/seed/vanilla/, vendored locally and gitignored (refresh with --vendor <Assets.zip>), and python tools/check_refs.py checks every art path the pack's JSON names.
